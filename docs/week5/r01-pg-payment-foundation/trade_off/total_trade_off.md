# R01 설계 질문·결정 목록

상태: **설계 논의 중·구현 전**. 확정한 제약과 미정 질문을 구분한다. 각 주제를 논의한 뒤 번호별 설계 문서를 추가하고 이 목록에 연결한다.

2026-10-21 [요구사항 분석](../requirement.md)에 G01~G08의 빈틈·확인 사항을 정리했다.
사용자 추가 조건으로 독립 실행하는 테스트 PG와 기존 MySQL의 PG 전용 스키마에 DB 저장하는 구성이 확정됐다. 메모리 저장 선택은 철회됐다.
먼저 00에서 테스트 PG의 실행·DB 구성을 논의한 뒤 나머지 주제를 한 가지씩 문답한다.

## 확정한 제약

- 로컬에서 독립 실행하는 작은 테스트 PG를 직접 만들고 commerce가 실제 HTTP로 연결한다. 원문의 세 HTTP 계약을 유지한다.
- PG 거래는 기존 MySQL의 PG 전용 스키마에 저장하며 PG 재시작 후에도 보존한다. 실제 카드·금전·외부 PG 계정은 사용하지 않는다.
- 생성 요청에 제공자 멱등 보장이 없다. 실제 HTTP timeout을 적용하고 create 자동 재시도를 차단한다.
- 내부 시도·외부 거래·주문을 구분하고, 주문당 한 시도·차감 처리 기록을 영속화한다.
- 과거 POINT 결제 사실을 보존하고 카드 번호는 저장·로그 출력하지 않는다.

라이브러리·테이블·클래스 이름·timeout 수치·마이그레이션 방식을 지금 선택한 것으로 기록하지 않는다.
PG의 독립 실행·DB 저장·기존 MySQL의 PG 전용 스키마 분리는 사용자 확정 사항이며 다시 미정으로 취급하지 않는다.
설계가 정해지면 대안·선택·이유·비용·미해결 한계를 기록하고 계획에 반영한다.
