# R01 설계 질문·결정 목록

상태: **설계 전·구현 전**. 아래 질문은 결정 사항이 아니다. 각 주제를 논의한 뒤 번호별 설계 문서를 추가하고 이 목록에 연결한다.

2026-10-21 [요구사항 분석](../requirement.md)에 G01~G07의 빈틈·확인 사항을 정리했다.
해결책은 미정이며, 먼저 01의 책임·소유권부터 한 주제씩 문답한다.

## 확정한 제약

- 로컬 테스트 PG의 원문 HTTP 계약을 사용하며 별도 PG 제품·관리 화면을 만들지 않는다.
- 생성 요청에 제공자 멱등 보장이 없다. 실제 HTTP timeout을 적용하고 create 자동 재시도를 차단한다.
- 내부 시도·외부 거래·주문을 구분하고, 주문당 한 시도·차감 처리 기록을 영속화한다.
- 과거 POINT 결제 사실을 보존하고 카드 번호는 저장·로그 출력하지 않는다.

## 앞으로 논의할 질문

| 번호 | 주제 | 확정할 내용 |
|---|---|---|
| 01 | 모델 소유권·상태 전이 | G01·G03·G04: 기존 OrderRecord와 결제 시도/사실의 구분, 발송·관찰·차감 처리 상태의 조합과 종결 불변식 |
| 02 | 저장·요청 일치·호환 | G02·G03·G05: 키의 유일성/입력 범위, 카드 비저장과 동일 요청 판정, 기존 POINT 호환·ddl-auto와 재기동 검증 |
| 03 | HTTP client·설정 | G06: 실제 client/request factory, timeout 수치·범위, 숨은 create 재시도 차단, 해석/전송 실패와 설정 검증 |
| 04 | adapter·fixture | G03·G04·G06·G07: 불완전 응답·확정 거절·최초 거래 키 검증, URI 처리, 같은 orderId의 중복 거래·응답 유실 통제 |

라이브러리·테이블·클래스 이름·timeout 수치·마이그레이션 방식을 지금 선택한 것으로 기록하지 않는다.
설계가 정해지면 대안·선택·이유·비용·미해결 한계를 기록하고 계획에 반영한다.
