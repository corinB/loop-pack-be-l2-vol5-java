## 실제 진행 기록

- 기능 구현: 미시작.
- 테스트·Checkstyle·ArchUnit: 미실행.
- 실제 시작 커밋: `4b81541e92e3afce2fbbba25342b979bb2328385`.
- 첫 설계 문답: 준비 TX 진입은 주문 상태 CAS로 선점하기로 확정했다. 상품 잠금·복구 작업 CAS·관찰 저장 경계는 유지한다.
- 재고 복구 문답: int 한도 초과는 업무 전체 rollback·PG 실패 보존·수동 처리로 확정했다. 담당자 원인 해소 후 저장된 근거로 재적용한다.
- 고객 소유권 문답: 기존 X-USER-ID로 confirm/고객 상세/reconcile의 주문 소유자를 비교하기로 확정했다. 과거 POINT 고객 상세도 포함하며 로그인 프레임워크는 추가하지 않는다.
- 고객 오류 문답: 타인 주문은 없는 주문과 같은 404·ORDER_NOT_FOUND·메시지로 응답하기로 확정했다. 주문 관련 관리자/운영 담당자 경로에 기존 1번 fixture 확인을 적용하기로 확정했다.
- 다음 문답: 공통 업무 반영도 주문 상태 CAS로 확정했다. 결제 시도 행/상품 변경 잠금·전체 업무 TX를 유지한다. callback은 요청 안의 동기 처리로 확정했다. 수동 대사는 저장된 종결 근거 재적용 시 조회 0회, 그 외 PG 조회 최대 1회로 확정했다. 자동 회차는 유지한다. 상세 계획 작성·세 관점 리뷰 전이다.
