# PR02 상세 계획의 세 관점 리뷰

2026-10-22 [상세 계획](plan.md) 초안을 비즈니스·사용자 경험·기술 서브에이전트가 각각 검토했다.
기능 코드·테스트 구현 리뷰가 아닌 구현 전 계획 검토다. 파일 수정·테스트 실행을 에이전트에게 맡기지 않았다.

상태: **중요 보완 3건 사용자 승인·계획 반영 및 세 관점 재리뷰 완료**. 기능 구현은 시작하지 않았다.

## 최초 리뷰 결과

| 관점 | 결과 |
|---|---|
| 비즈니스 | 구현을 막는 중요 누락 없음. 완료된 반복 대사의 빠른 반환을 명시하는 선택 보완 1건. |
| 사용자 경험 | 이미 업무 반영 완료 후 생긴 충돌을 미완료 202와 구분하는 중요 보완 1건. 후속 행동 예시의 선택 보완 2건. |
| 기술 | 실패 표식의 기준 snapshot 시점, save 제거/confirm 전환의 커밋 순서에 중요 보완 2건. 핵심 CAS·짧은 TX·수동 예산 보존 방향은 적절. |

## 중요 보완 최소안 · 2026-10-22 사용자 승인 및 계획 반영

사용자가 세 가지 보완을 함께 승인했다. 아래는 최초 지적과 승인한 해결 방법이며 [상세 계획](plan.md)에 반영했다.

### 1. 완료된 주문의 늦은 충돌과 미완료를 구분

주문 확정·재고 소비·APPLIED 저장이 끝난 뒤 PG 종결 상충이 기록될 수 있다.
이를 계속 202로 응답하면 호출자가 아직 업무가 진행 중이거나 반복 대사로 해결될 것이라 오해할 수 있다.

업무 반영 완료 여부를 200/202의 기준으로 통일했다.
이미 반영했다면 200과 기존 완료 상태·충돌 주의 표시를 반환하고, 미반영 충돌은 202와 수동 확인 필요를 반환한다.
GET의 조회 성공 200은 유지하며 강제 충돌 해소·환불 API는 추가하지 않는다.

### 2. 실패 표식은 업무 시도 당시 snapshot으로 CAS

callback 실행 A의 업무가 rollback된 뒤 수동 실행 B가 인계받을 수 있다.
A가 실패 후 최신 B를 다시 읽어 expected 값으로 쓰면 CAS라도 B를 수동 필요로 바꿀 수 있다.

업무 시도 직전 또는 해당 업무 TX에서 확인한 작업 상태·실행 ID·사용 회차를 변경 불가능한 비교값으로 실패 기록기에 전달하도록 명시했다.
실패 후 최신 소유자를 새 기준으로 삼지 않는다. 당시 READY였다면 READY/ID 없음/회차 0도 그대로 비교한다.
조건이 바뀌었거나 APPLIED면 예전 실패 기록은 적용하지 않는다.

### 3. 범용 save 제거와 기존 confirm/테스트 이행을 같은 커밋에서 수행

초안은 커밋 2에서 save를 제거하고 커밋 5에서 기존 confirm·POINT 테스트를 전환한다.
그러나 현재 OrderService.confirm과 저장 실패 주입·기존 POINT fixture가 save를 사용하므로 중간 커밋 Green을 유지할 수 없다.

insert/CAS를 먼저 추가하고 최종 save 제거를 confirm 전환 커밋으로 옮겼다.
기존 confirm 전환·관련 테스트/fixture 이행·범용 save 제거를 함께 검증한다. 기존 주문 갱신을 insert로 바꾸거나 임시 POINT facade를 추가하지 않는다.
기반 단계에서도 기존 POINT confirm은 DRAFT만 허용해 새 PG 상태를 POINT로 확정하지 않게 한다.

## 함께 반영한 설명 보완

- 소유권 확인 후 이미 업무 반영 완료라면 claim/인계·PG 조회 없이 저장 상태를 반환하는 빠른 경로를 명시한다. 충돌 표시는 유지한다.
- R02의 202 다음 행동을 예시로 설명한다. GET은 저장 상태만 읽고 실제 재확인은 POST reconcile이며 자동 재조회는 R03이다.
- overflow 수동 처리 예시는 PG 실패 보존→관리자 가용 수량의 원인 해소→저장 근거 재적용(PG GET 0회)을 보여준다.
- 공유 Gateway spy 설정은 doReturn/doAnswer 계열을 사용해 설정 중 실제 HTTP가 실행되지 않게 한다.

## 승인 후 재리뷰

승인한 세 가지와 함께 반영한 설명을 같은 세 서브에이전트가 다시 검토했다.

| 관점 | 재리뷰 결과 |
|---|---|
| 비즈니스 | 중요 지적 없음. 선차감·실패 한 번 복구·PG 근거와 과거 POINT 보호가 유지되며 완료 대사의 빠른 반환도 반영됐다. 구현 진행 가능. |
| 사용자 경험 | 기존 중요 지적 해소. 완료 후 충돌의 200/미반영 충돌의 202, GET/POST 역할과 반환 실패 후 수동 처리 안내가 일관된다. 추가 보완 없이 구현 진행 가능. |
| 기술 | 기존 중요 지적 2건 해소. 실패 당시 비교값의 CAS와 새 실행 보호, save 제거/confirm 전환의 커밋 결합이 명확하다. 추가 보완 없이 구현 진행 가능. |

이번 변경은 준비 문서뿐이므로 기능 테스트를 실행하지 않았다. 연결 문서의 로컬 링크 113개·diff 형식·브랜치명을 확인했고 기존 JMeter 변경과 원문 두 파일의 SHA-256이 유지됨을 확인했다.
계획 수정은 기능 구현·테스트 완료를 뜻하지 않는다. 다음 기능 작업은 계획의 커밋 2인 주문 PG 상태·조건부 저장·재고 반환 기반이다.
기능별 관련 검사·커밋 전 세 관점 리뷰·중요 수정 사용자 확인 원칙과 기존 변경 보존은 유지한다.
