## 주문·API·멱등성

- 미확정 DRAFT 주문의 결제는 PG를 사용하며 포인트를 차감하지 않는다. 금액은 저장된 주문에서 결정한다.
- confirm은 내부 시도 키와 합성 카드 입력을 받고, 미완료 결과는 202·주문/시도 상태·조회 경로를 반환한다.
- 주문 GET은 조회 전용이며 새 결제를 만들지 않는다. 결제수단·시도·최종 결과를 고객/관리자 조회에 연결한다.
- 같은 주문·시도의 동시 confirm에서 발송 권한을 얻은 실행 하나만 PG POST를 호출한다.
- 같은 키의 다른 주문·금액·실제 테스트 조건은 충돌이다. 사용자 요청으로 카드 입력은 재요청 비교에서 제외한다. 같은 주문의 다른 키도 두 번째 시도를 만들지 않는다.
- 실제 적용할 PG 테스트 조건도 동일 요청 비교에 포함한다. 같은 주문·키라도 조건이 다르면 충돌이며 최초 조건을 유지한다. 프리셋 이름/JSON 순서 자체가 아닌 적용 조건이 기준이며 정규화·저장 방식은 R01 상세 설계에서 정한다.
- 같은 주문·키·저장 금액·실제 테스트 조건이면 정상 형식의 카드 종류/번호가 바뀌어도 기존 상태를 반환한다. 재요청 카드로 결제를 바꾸거나 추가 create/재고 차감을 하지 않는다. 카드 기반 비교값/HMAC 저장은 범위 밖이며 카드 원문 비저장/로그 금지는 유지한다.
- 키는 [전체 결제 시도에서 전역 유일](../r01-pg-payment-foundation/trade_off/02-idempotency-request-contract.md)하다. 다른 고객의 같은 문자열도 다른 주문에 사용할 수 없다. 충돌로 다른 고객의 주문/결제 정보를 반환하지 않으며 접근 검증·오류 우선순위는 상세 설계에서 정한다.
- 동일 PG 시도의 종결 후 재요청은 저장 결과를 반환한다. 과거 POINT 확정 주문은 기존 재확정 오류를 유지한다.
- 발송 시작 기록 이후 재시작·timeout·조회 0건을 이유로 create를 다시 보내지 않는다.
- 2026-10-22 결정: 고객 confirm/상세/reconcile에 기존 X-USER-ID 기반 주문 소유권 검사를 적용한다. 과거 POINT 고객 상세도 같은 규칙이며 실제 로그인·Spring Security는 추가하지 않는다. [소유권 결정](trade_off/04-customer-ownership-and-api.md)을 따른다.
- 타인 주문은 없는 주문과 같은 404·ORDER_NOT_FOUND·메시지로 응답한다. 소유권 거절 시 기존 결제 결과나 상태를 먼저 반환하거나 재고·PG·작업 진행을 변경하지 않는다. 관리자/운영 담당자 접근 범위는 후속 선택 대상이다.

## 재고 차감·실패 복구·트랜잭션

- application 파사드가 주문·pay 결제 시도/복구 작업·mall 재고 처리 모델을 조율한다. 현재 ConfirmOrderFacade의 전체 단일 TX는 PG 흐름에 맞게 분리한다.
- 전체 흐름은 준비 TX A → TX 밖 PG HTTP → 검증 결과 저장 TX → 공통 업무 반영 TX B다. [A안과 후속 보완](trade_off/01-facade-transaction-boundary.md)에 따라 조율 파사드와 준비/검증 결과 저장/공통 업무 반영의 별도 Spring 빈을 둔다. 짧은 TX는 각 컴포넌트의 공개 @Transactional 진입점에 둔다.
- TX A에서 주문·품목·저장 금액·상품 삭제·재고를 검사하고 재고 차감·주문별 차감 기록·시도·발송 상태를 저장한다.
- 2026-10-22 결정: TX A 진입은 주문 DRAFT에서 PAYMENT_PENDING으로의 CAS로 선점한다. 성공자만 준비하고 commit 정상 반환 후 PG를 호출한다. 실패자는 최신 저장 상태를 확인하며 일반 save로 과거 DRAFT를 덮어쓰지 않는다.
- 부족·삭제·잘못된 입력은 PG 호출 없이 TX A 전체를 rollback한다. PG HTTP는 TX 밖에서 실행한다.
- TX B에서 검증된 외부 결과와 주문·시도·차감 기록을 함께 보호하고 한 번만 적용한다.
- 재고 차감·복구 기록은 mall의 별도 모델이다. 확정 실패 반영 시 상품 재고 증가와 복구 완료 기록·관련 주문/결제/작업 변경을 같은 TX에서 commit하고 중간 실패는 함께 rollback한다. 별도 비동기 재고 복구 worker는 두지 않는다.
- SUCCESS는 주문을 확정하고 이미 차감한 재고를 유지한다. FAILED 또는 계약에 맞는 효과 0건 확정 거절만 수량을 한 번 복구한다.
- PENDING·UNKNOWN·조회 불가·0건·복수/불일치에는 임의 성공·실패·복구를 하지 않는다.
- 성공/복구 반영의 DB 실패는 해당 TX를 rollback한다. 기존 거래 재조회로 같은 결과를 다시 적용할 수 있어야 한다.
- 검증 결과는 TX B 전에 별도 commit하며 TX B rollback에도 보존한다. 저장된 신뢰할 종결 결과가 미반영이면 PG 재조회 없이 재적용할 수 있다. 거래 없는 확정 거절도 저장한 근거로 복구하며 404/빈 목록으로 실패를 추론하지 않는다. 관찰 저장 전 종료는 미확인으로 유지한다.
- 관리자 재고 설정은 이미 확보한 주문 수량을 지우지 않고 가용 수량을 최종 설정하는 의미를 유지한다.
- 2026-10-22 결정: 재고 반환이 int 한도를 넘으면 업무 TX 전체를 rollback하고 이미 저장한 PG 실패는 보존해 수동 확인 대상으로 남긴다. 원인 해소 후 같은 근거를 재적용한다. [재고 복구 결정](trade_off/02-stock-restore-and-admin-update.md)을 따른다.
- 차감 후 삭제된 상품은 저장된 주문·금액·차감 기록으로 PG 결과를 마무리한다. 실패 복구가 상품을 다시 노출하지 않게 한다.
- 차감과 복구의 commit/rollback을 기존 상품 상세 캐시 정책에 연결한다.

## callback·수동 대사

- `POST /api/v1/orders/{orderId}/payment/reconcile`은 미완료 시도의 기존 거래를 조회·반영한다.
- 장애 중단 작업은 재시작 후 자동 재개하지 않고 [운영 담당자가 미완료 목록을 조회해 수동 대사](trade_off/06-interrupted-payment-reconcile.md)한다. 정상 @Retryable 최초+추가 3회는 유지하고 사용 기록은 보존한다.
- 목록 GET은 조회 전용이다. 명시적 POST 대사는 미완료 작업의 현재 실행 ID·상태를 조건으로 새 실행 ID를 기록하고 옛 진행 갱신을 차단한다. 저장된 검증 종결 결과의 재적용 또는 권위 조회/새 관찰 저장 후 공통 업무 반영 TX를 사용한다. 정확한 목록 계약·인계 조건식/응답은 상세 설계에서 정한다.
- `POST /api/v1/payments/callback`은 원문의 providerOrderId·transactionKey·status 알림을 받아 PG 권위 조회로 확인한다.
- 제공자 계정 범위·주문·거래 키·저장 금액을 검증한 관찰만 공통 결과 적용 경계에 전달한다.
- R03의 자동 재확인도 기존 거래 조회·공통 결과 적용 경계를 재사용한다. 자동 재확인·수동 전환 정책은 [별도 논의](../r03-payment-resilience/trade_off/01-reconciliation-retry-policy.md)를 따른다.
- callback-first·lookup-first·동시 적용은 같은 상태와 효과 수로 수렴해야 한다.
- 종결 뒤 상충하는 결과를 덮어쓰지 않는다. 늦은 생성 응답·timeout handler가 종결을 PENDING/UNKNOWN으로 되돌리지 못하게 한다.

## 완료 조건·대표 검증

- [ ] 정상 PG 주문: 외부 거래 1건·create 1회·주문 확정·추가 재고 차감 0회·포인트 변화 0.
- [ ] 재고 5개/주문 2개: 시작 후 3개, 성공 후 3개, 확정 실패 후 5개, 중복 실패 후에도 5개.
- [ ] PENDING·거래 생성 후 응답 유실: 차감 상태 유지·미완료 응답·추가 create 0회.
- [ ] 같은 시도의 동시 confirm·다른 키·요청 불일치에서 시도·차감·발송이 중복되지 않는다.
- [ ] 실제 callback controller에서 위조/불일치 본문만으로 성공하지 않고 중복·순서 변경·동시 대사가 추가 효과를 만들지 않는다.
- [ ] 내부 저장 실패·종결 충돌·늦은 응답을 통제해 rollback과 종결 상태 보호를 확인한다.
- [ ] 확정 거절/성공 관찰 저장 뒤 업무 반영 TX rollback·재시작에도 근거가 보존되고 한 번만 재적용된다. 거래 없는 거절 재적용에 PG의 빈 목록을 실패 근거로 쓰지 않는다.
- [ ] 수동 대사의 실행 ID 교체 뒤 옛 실행의 진행/회차 갱신과 오래된 save가 최신 상태를 덮어쓰지 못한다.
- [ ] 재시작 후 시도·작업·횟수·차감 기록을 유지하고 미완료 목록에서 찾아 수동 대사로 회복한다. 목록 조회가 PG 호출/재고 변경을 만들거나 중단 자동 작업을 재개하지 않는다.
- [ ] 과거 POINT·삭제·관리자 재고·캐시·소유권 정책의 결정 범위를 검증하고 관련 회귀·Checkstyle·ArchUnit을 확인한다.

개별 기능 테스트는 이 PR에 포함한다. R03은 회복 도구와 여러 경로를 엮는 장애 실험을 보강한다.
