# R02 설계 질문·결정 목록

상태: **설계 전·구현 전**. R01 병합 결과를 확인한 뒤 번호별 주제를 논의하고 결정 문서를 연결한다.

## 확정한 제약

- 재고를 먼저 차감해 commit한 뒤 PG를 호출한다. 성공 시 유지, 확정 실패 시 한 번 복구, 미확인 시 차감 상태 유지다.
- 외부 HTTP는 DB TX 밖에서 실행한다. 주문당 한 시도이며 발송 시작 후 create를 자동 재시도하지 않는다.
- callback·대사는 권위 조회·동일 거래 검증을 거쳐 공통 결과 적용 경계를 사용한다.
- 신규 PG 결제에서 포인트를 차감하지 않고 과거 POINT 기록·재확정 오류는 보존한다.

## 앞으로 논의할 질문

| 번호 | 주제 | 확정할 내용 |
|---|---|---|
| 01 | TX·잠금·발송 권한 | 기존 facade 분리, 시도/주문/상품 잠금 순서, 동시 confirm의 발송 권한과 예외 경계 |
| 02 | 재고 처리·복구 | R01 기록 모델의 적용, 관리자 설정과 경쟁, 차감 후 삭제 상품의 복구/종결, 캐시 이벤트 |
| 03 | 공통 결과 적용 | 관찰 검증 책임, 중복/충돌 보존, terminal 상태 보호, 내부 저장 실패 후 재적용 |
| 04 | API·사용자 경계 | confirm 입력·202/200·조회 경로·오류 매핑, fixture 기반 소유권/관리자 구분의 적용 범위 |
| 05 | callback·대사·재시작 | 키 유무별 조회 흐름, 알림 수신 계약, 0건/복수/불일치 처리, 프로세스 재생성 실험 |

특히 소유권은 기존 정책과 원문의 차이다. 적용 범위를 확인하기 전에 기존 보장을 있다고 쓰거나 새 인증 체계를 확정하지 않는다.
정확한 DTO·잠금 순서·충돌 기록 형식·오류 코드·클래스 배치는 설계 결정 후 계획에 반영한다.
