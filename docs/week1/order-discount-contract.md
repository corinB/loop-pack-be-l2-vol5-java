# 주문 할인 설계 기록

## 목적

확인된 제품 약속·실습용 전제·제품 질문을 분리하고, 다음 구현자가 정책을 추측하지 않도록 구현 가능한 설계 기록을 만든다.

## 현재 상태

- 질문 17개·영향 17개·필요한 정보 18개(조건부 후보 2개 포함), 추가 제안 해당 없음, UC-001, INV-001~006의 규칙·반례·기대 결과·책임 후보를 사용자 검토 후 기록했다. 다음은 규칙 간 충돌 검토 후 API 계약을 함께 작성한다. 미확인 정책·UC 세부 상태와 P-002 추가 질문 보류는 유지하며 과제 전체 완료는 아니다.
- 질문을 선택한 것이며 제품의 답은 모두 **미확인**이다.
- 문서 양식만 준비했다. 작성란이 있다는 이유로 해당 과제를 완료한 것으로 표시하지 않는다.
- `미작성`: 아직 작성하지 않은 항목. `미확인`: 정책의 답이 없는 항목. `관찰 예정`: 아직 측정하지 않은 결과.

학습 재개 기록: [CHECKPOINT.md](CHECKPOINT.md). 작업 브랜치: `docs/week1-design-checkpoint`.
