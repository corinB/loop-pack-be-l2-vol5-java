## 규칙별 책임 연결

규칙 본문은 invariants.md에 두고, 여기에는 책임과 이유를 연결한다.

| 규칙 ID | 책임 후보 | 선택 이유 | 보장할 상태·행동 | 검토 사례 |
|---|---|---|---|---|
| INV-001 | 쿠폰 사용 가능 여부를 확인하는 부분 | 요청자와 쿠폰 보유자를 비교해 사용 가능 여부를 판단해야 하기 때문 | 요청자가 보유하지 않은 쿠폰을 적용하지 않고 적용 불가를 알린다. | 구매자 A가 구매자 B의 쿠폰을 적용하려고 한다. |
| INV-002 | 주문의 쿠폰 적용 상태를 관리하는 부분 | 주문에 현재 적용된 쿠폰을 확인하고 개수를 제한해야 하기 때문 | 두 쿠폰이 동시에 적용된 상태를 만들지 않는다. | 쿠폰 A가 적용된 주문에 B도 추가해 두 쿠폰의 할인이 함께 반영된다. |
| INV-003 | 할인 금액과 최종 금액을 계산하는 부분 | 계산한 금액들이 주어진 계산식을 만족하도록 보장해야 하기 때문 | 최종 금액 = 원금 − 할인 금액을 만족한다. | 원금 10,000원, 할인 금액 1,000원인데 최종 금액이 8,000원으로 나온다. |
| INV-004 | 확정된 할인 결과를 관리하는 부분 | 이후 변경이 발생해도 확정된 할인 금액을 보존해야 하기 때문 | 할인 금액이 확정되면 이후에도 그 금액을 유지한다. | 할인 금액을 1,000원으로 확정했는데 쿠폰 정책 변경을 이유로 2,000원으로 변경한다. |
| INV-005 | 요청 식별과 이전 결과 재사용을 조정하는 부분 | 같은 요청인지 판단하고 해당 요청의 이전 결과를 찾아 연결해야 하기 때문 | 같은 요청이 다시 들어오면 이전 처리 결과를 재사용한다. | 같은 요청으로 판단된 재요청에 처음의 할인 금액 1,000원 대신 새로 계산한 2,000원을 반환한다. |
| INV-006 | 쿠폰 사용 가능 여부를 확인하는 부분 | 요청 시작 시각과 쿠폰 만료 시각을 비교해 만료 여부를 판단해야 하기 때문 | 요청 시작 시각을 기준으로 쿠폰 만료 여부를 판단한다. | 만료 시각 12:00:00 전에 11:59:59에 시작한 요청을 처리 시각 12:00:01 기준으로 만료라고 판단한다. |

## 점검

- [ ] 여섯 규칙의 책임 후보와 선택 이유를 작성했다.
- [ ] 각 책임이 보장할 상태와 행동을 기록했다.
- [ ] 세 결정마다 선택 방식·버린 대안·선택 이유를 작성했다.
- [ ] 결정의 근거와 미확인 정책을 구분했다.
- [ ] 처리 순서를 맡을 경계와 호출자가 알아야 할 내용을 검토했다.
