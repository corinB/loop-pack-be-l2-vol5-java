# 요구사항과 제품 질문

[전체 설계 기록](order-discount-contract.md)

> 작성 상태: 사용자와 합의한 질문 17개로 질문 초안 작성을 마무리했다. P-001 4개·P-002 1개·A-001~004 각 3개다. 질문 17개에 대한 영향과 필요한 정보 18개(조건부 후보 2개 포함)를 모두 기록했고 정책 답은 모두 미확인이다. P-002 추가 질문은 사용자 요청으로 보류했다.

## 1. 출처와 작성 원칙

- 기준은 사용자가 제공한 이번 과제의 입력이다. 수업의 가상 정책을 확정된 제품 정책으로 옮기지 않는다.
- `P-001~002`: 제품 약속. `A-001~004`: 실습용 전제.
- 질문은 **조건마다 3~5개** 작성한다. 다른 조건의 Q1과 혼동하지 않도록 참조할 때는 `P-001/Q1`처럼 조건 ID를 함께 쓴다.
- `미작성`은 빈 작성란, `미확인`은 아직 없는 정책의 답을 뜻한다.
- 질문 선택은 정책 승인과 다르다. 답을 받았을 때 확인 근거와 변경 영향을 함께 기록한다.

## 2. 확인된 제품 약속

| ID | 과제 원문 |
|---|---|
| P-001 | 구매자는 주문 확정 전에 보유 쿠폰을 적용할 수 있다. |
| P-002 | 확정된 할인 금액은 이후에도 유지된다. |

## 3. 이번 과제의 실습용 전제

실제 제품 정책으로 확정된 조건이 아니라, 이번 과제의 설계 범위를 좁히기 위한 입력이다.

| ID | 과제 원문 |
|---|---|
| A-001 | 한 주문에는 쿠폰 한 장만 적용한다. |
| A-002 | `finalAmount = originalAmount - discountAmount`로 계산한다. |
| A-003 | 같은 요청의 결과를 재사용한다. |
| A-004 | 쿠폰 만료 여부는 요청 시작 시각을 기준으로 판단한다. |

## 4. 범위와 제약

과제에서 지정한 제약: `docs/week1`과 `ContractClassificationTest`만 수정하고, 제품 코드·build/dependency를 변경하지 않는다. 주문 할인 제품 기능은 구현하지 않는다. 기존 동작 관찰은 나중에 진행한다.

| 구분 | 내용 | 근거 또는 관련 조건 | 상태 |
|---|---|---|---|
| 이번 설계에 포함할 사용 장면 | 미작성 | 미작성 | 미작성 |
| 이번 설계에서 제외할 사용 장면 | 미작성 | 미작성 | 미작성 |
| 추가로 확인할 범위·제약 | 미작성 | 미작성 | 미확인 |

‘조건부 정보’는 정책 답변에 따라 필요성이 결정되는 후보이다. ‘할인 금액’과 ‘확정 당시 할인 금액’은 의미를 구분한 것이며, 별도 필드 두 개가 필요하다고 정한 것은 아니다.

## 6. 조건별 제품 질문

질문 초안은 17개로 마무리했다. 남은 빈 질문란은 추가로 선택한 질문이 아니며 작성된 질문 수에 포함하지 않는다. 선택한 질문 17개의 영향도 모두 기록했다. 조건마다 3~5개 기준에서 P-002는 1개인 채 보류 중이므로 관련 전체 완료 항목은 체크하지 않는다.

## 7. 출처가 부족한 제안 처리

현재 과제 기록을 검토하고, 사용자가 대화 밖에서 받은 추가 정책 제안도 없다고 확인했다. 미확인 정책은 질문 목록으로 관리하며 설명용 가상 예시는 실제 정책 제안으로 취급하지 않는다.

| 제안 | 제안 출처 | 제품 근거 | 보류·거절 등 처리 | 이유 | 연결할 질문 또는 결정 |
|---|---|---|---|---|---|
| 해당 없음 | 사용자 확인 — 외부에서 받은 추가 제안 없음 | 해당 없음 | 해당 없음 | 이번 과제에서 별도로 검토할 출처 없는 제품 정책 제안은 없었다. | 미확인 정책은 6절의 질문 목록으로 관리 |

## 8. 액터와 사용 흐름

사용자가 검토한 쿠폰 적용 유스 케이스다. 세부 흐름과 상태는 후속 단계에서 필요한 만큼 구체화한다.

| 항목 | 내용 |
|---|---|
| ID | UC-001 |
| 이름 | 주문에 쿠폰 적용 |
| 액터 | 구매자 |
| 목적 | 주문에 할인을 적용하고 할인 후 금액을 확인한다. |
| 시작 사건 | 구매자가 주문과 쿠폰을 선택해 적용을 요청한다. |
| 기본 조건 | 주문 확정 전이며, 구매자가 보유한 쿠폰이어야 한다. |
| 기본 흐름 | 적용 가능 여부 확인 → 할인 금액·최종 금액 계산 → 적용 결과 전달 |

기본 조건은 P-001 제품 약속에 근거한다. 만료나 금액 제한의 구체적인 처리 방식은 답변을 받은 뒤 보완한다. 성공·실패 후 저장 상태나 세부 분기를 이 표만으로 확정하지 않는다.
