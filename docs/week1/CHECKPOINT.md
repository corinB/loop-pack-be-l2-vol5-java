# 1주차 과제 체크포인트

## 현재 상태

- 1~6강 설명 완료. 과제 3단계의 여섯 규칙 초안을 기록했고 충돌 검토와 2단계 보류 사항은 남아 있다.
- 사용자 요청으로 **확인할 질문 초안 17개 작성을 마무리**했다. 추가 질문을 임의로 늘리지 않는다.
- 질문의 정책 답변은 모두 **미확인**이다. 질문 선택과 정책 확정은 다르다.
- 질문 17개·영향 17개·필요한 정보 18개(조건부 후보 2개 포함)를 기록했다. 과제 2단계 전체 완료는 아니다.
- 다음 재개 위치: **규칙 간 충돌과 미확정 사항**을 함께 검토한 뒤 API 계약으로 진행한다. INV-001~006을 기록했다. UC-001의 기본 항목은 기록했고 세부 상태는 미확정이다.

## 진행 원칙

- 기본은 한 질문씩 문답한다. 요청 시 표로 일괄 제안하되 핵심만 짧게 보여준다. 복잡한 초안은 채택하지 않았다. 간결하게 쓰되 ID·액터·목적·시작 사건·기본 조건 등 필수 항목은 유지한다.
- 기본 계산 이해도 확인보다 설계에 필요한 정책·판단을 중심으로 진행한다.
- 규칙·API·책임·설계 대안의 답을 혼자 작성하거나 가상 정책으로 채우지 않는다.
- 기존 강의는 유지하되 수업의 가상 사례나 삭제한 초안의 판단을 과제 답으로 복구하지 않는다.
- 미작성: 아직 쓰지 않음 / 미확인: 정책 답이 없음 / 관찰 예정: 실측 전.
- 원래 질문 기준은 조건마다 3~5개다. P-002는 사용자 요청으로 1개에서 보류했고 초안 작성은 마무리했다.

- Java 저장소: `Loop/loop-pack-be-l2-vol5-java`, 과제 폴더: `docs/week1`, 작업 브랜치: `docs/week1-design-checkpoint`.
- 기준 commit: `313abe5821abd4bde6b29e2a16a849177cff01e2`. 사용자가 이 위치에서 진행하도록 승인했다.
- 같은 승인을 다시 묻지 않는다. 위 commit은 작업 시작 기준이며 현재 HEAD와 다를 수 있다. 가이드 일치 여부는 별도 확인 사항이다.
- 과제 수정 허용: `docs/week1`과 `ContractClassificationTest`.
- 제품 코드·`apps/commerce-api/src/main`·build/dependency는 수정하지 않는다.
- 이번 주에는 주문 할인 제품 기능을 구현하지 않는다.
- 기존 API 관찰·테스트는 나중에 진행하며, 결과를 추정하거나 별도 curl 로그를 제출하지 않는다.

## 과제에서 주어진 입력

| 구분·ID | 원문 |
|---|---|
| 제품 약속 P-001 | 구매자는 주문 확정 전에 보유 쿠폰을 적용할 수 있다. |
| 제품 약속 P-002 | 확정된 할인 금액은 이후에도 유지된다. |
| 실습 전제 A-001 | 한 주문에는 쿠폰 한 장만 적용한다. |
| 실습 전제 A-002 | `finalAmount = originalAmount - discountAmount`로 계산한다. |
| 실습 전제 A-003 | 같은 요청의 결과를 재사용한다. |
| 실습 전제 A-004 | 쿠폰 만료 여부는 요청 시작 시각을 기준으로 판단한다. |

실습 전제는 과제 범위를 좁히기 위한 입력이며 실제 제품 정책으로 확정된 것이 아니다.

정확한 질문 문장과 기록된 영향은 [requirements.md](requirements.md)를 기준으로 한다. 아래는 재개용 요약이다.

|---|---|---|
| P-001 · 4개 | Q1 주문 확정 사건 / Q2 확정 전 적용 결과 저장 여부 / Q3 다른 쿠폰으로 교체 여부 / Q4 다른 주문에도 적용 가능한지와 첫 주문 확정 전후의 차이 | 4개 기록 |
| P-002 · 1개 | Q1 할인 금액 확정 시점과 주문 확정 시점의 관계 | 1개 기록, 추가 질문 보류 |
| A-001 · 3개 | Q1 확정 전 적용 취소 / Q2 자동 적용 여부 / Q3 자동 적용한다면 그 시점 | 3개 기록 |

- 재사용 기간 질문은 사용자가 추가하지 않고 넘어가기로 했다.
- 질문의 답을 기다리는 것과 API 응답 표현·내부 저장 방식을 설계하는 것을 구분한다.

## 다음 진행 순서

1. 필요한 정보 18개는 사용자 일괄 검토 후 기록했다. 조건부 후보·미확인 사항을 유지하며 필드·저장 구조를 미리 확정하지 않는다.
2. 추가 정책 제안이 없음을 사용자에게 확인하고 해당 없음으로 기록했다. 사용자가 승인한 UC-001의 ID·액터·목적·시작 사건·기본 조건·흐름·결과도 기록했다. 저장·교체·취소·만료 정책과 세부 상태는 미확정이다.
3. INV-001~006은 합의해 기록했다. 규칙 간 충돌 검토 → API 계약 → 책임과 설계 대안 → 문서 추적표를 함께 작성한다.
4. 미룬 기존 API 관찰과 테스트를 실행하고 실제 결과를 기록한다.
5. 기술 글 작성 후 최종 검증한다. 분할 제출의 가이드 적합성과 지정 commit 일치 여부도 확인한다.

이 체크포인트의 커밋용 사본은 Java 저장소의 docs/week1/CHECKPOINT.md에 저장한다. 미확인 답과 보류 사항을 유지하며 전체 과제 완료로 표시하지 않는다.
