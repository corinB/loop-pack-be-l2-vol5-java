# 1주차 과제 체크포인트 — 설계 문서만 진행

## 현재 상태와 다음 작업

- 1~6강 설명 완료. 현재는 멘토의 구체화된 안내를 반영해 설계 문서만 진행한다.
- 사용자 요청으로 기존 질문 17개·영향 17개를 모두 유지한다. 질문 축소·선별 단계는 진행하지 않는다.
- 필요한 정보 18개(조건부 후보 2개), 추가 제안 해당 없음, UC-001, INV-001~006과 책임 후보를 기록했다.
- 성공 후 만료(INV-005·006)와 주문 확정(P-001·INV-005) 뒤 재요청 사례를 질문으로 기록했다. 정책 답·우선순위·금액 경계·UC 세부 상태는 미확인이다.
- INV-004에 할인 한도 변경 후에도 확정된 할인 금액을 보존하는 사례를 기록했다. 한도 존재·금액은 설명용 가정이다.
- API 필수 양의 정수 ID·성공/오류 계약·요청/응답 예시와 세 설계 결정을 기록했다. 금액 표현·저장 시점·정책 답·검사 우선순위는 미확인이다. 대표 문서 통합·문서 대조를 완료했다. 다음은 **통합 문서를 함께 읽고 남은 미확인·미정 항목을 검토**한다.

## 범위와 진행 원칙

- 분할 문서로 계속 공부한다. 최종적으로 대표 문서에 필수 설계 내용을 직접 통합한다.
- 관련 항목을 짧은 표로 묶어 한 번에 검토받고, 승인한 내용만 기록한다.
- 설명은 쉽게 하되 ID·액터·목적·시작 사건·기본 조건 등 필요한 항목은 유지한다.
- 제품 질문·실습 조건·학습자가 선택할 설계를 구분한다. 정책 답과 오류 코드·저장 방식을 임의로 확정하지 않는다.
- 멘토 안내의 질문 수는 전체 3~5개다. 사용자는 더 넓게 검토한 17개를 통합 문서에도 모두 유지하기로 했다.
- 기술 글, 테스트 코드 작성·기존 테스트 실행, 실제 HTTP 요청·관찰은 **이번 범위 제외·추후 진행**이다.
- 제품 코드·기존 테스트·build·dependency를 변경하지 않는다. 별도 검증 폴더 생성과 Git 기준점 변경도 제외한다.
- 커밋은 사용자가 담당한다. 문서 범위 완료와 멘토 과제 전체 완료는 구분한다.
- 기존 강의·학습 기록을 유지한다. 삭제한 초안이나 수업의 가상 정책을 과제 답으로 복구하지 않는다.

## 확인된 제품 약속과 실습 조건

| 구분·ID | 내용 |
|---|---|
| 제품 약속 P-001 | 구매자는 주문 확정 전에 보유 쿠폰을 적용할 수 있다. |
| 제품 약속 P-002 | 확정된 할인 금액은 이후에도 유지된다. |
| 실습 조건 A-001 | 한 주문에는 쿠폰 한 장만 적용한다. |

| 실습 조건 A-004 | 쿠폰 만료 여부는 요청 시작 시각을 기준으로 판단한다. |

실습 조건은 실제 제품 정책으로 확정된 것이 아니다. 기준 문장 원문과 질문·영향은 [requirements.md](requirements.md)에 있다.

| 조건 | 질문과 작성 상태 |

## 앞으로의 순서와 문서 완료 기준

1. 기존 질문 17개를 유지하며 규칙·충돌을 보완한다. 금액 경계·만료 경계·재요청과 만료/확정 조건의 관계를 검토한다.
2. 사용자 식별·요청·성공·오류 계약과 요청/응답 예시·오류별 다음 행동을 정한다.
3. 오류 표현·snapshot/재계산·호출 순서 조정 경계의 세 결정을 비교하고 선택·버린 대안·이유를 기록한다.
4. 대표 문서 통합 완료. 질문/영향 17개·정보 18개·규칙 6개·결정 3개를 대조했고, 분할 문서 6개는 그대로 유지했다.
5. 목차·상세 참고 링크·표·JSON 예시 확인 완료. 미확인 정책·금액 표현·저장 시점·세부 구현 설계는 남아 있으며 과제 전체 완료가 아니다.

기본 API는 POST /api/v1/orders/{orderId}/discount, 요청은 couponId, 성공 정보는 주문 ID·원금·할인 금액·최종 금액이다. 기능 구현은 하지 않는다.
이 체크포인트의 사본은 저장소의 docs/week1/CHECKPOINT.md에 둔다. 관찰·테스트·기술 글은 이번 문서 완료 조건에서 제외한다.
