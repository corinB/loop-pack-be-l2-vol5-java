출발점은 `corinB`의 `d30c06e`이며, 기준 브랜치는 `volume-3/main`이다.
문서 작성은 기능 구현이나 테스트 통과를 뜻하지 않는다.

## 핵심 결정

- 주문 생성은 DRAFT와 주문 품목만 저장한다. 재고·포인트의 가용량을 검사하거나 선점·차감하지 않는다.
- 상품 존재·삭제 여부, 주문 수량·금액의 유효성 검사는 생성 시에도 유지한다.
- 확정 시 비관적 잠금으로 주문·재고·포인트를 보호하고 모든 변경·기록을 한 트랜잭션으로 저장한다.
- 브랜드와 연결된 미삭제 상품은 각 도메인의 `delete()`와 명시적 저장으로 함께 논리 삭제한다.
- 인증·인가·본인 여부 검사는 학습 범위 합의에 따라 제외한다. 원문 요구를 충족한 것으로 기록하지 않는다.
- 재고 예약, DRAFT 10분 만료, 자동 반환, Quartz 논의는 철회했다. 이번 구현 범위가 아니다.

## 이전 주차와의 관계

[week2 설계](../week2/README.md)와 [개발 컨벤션](../week2/conventions.md)의 계층·Context 소유권,
순수 도메인·Mapper, 입력·응답, TDD·검사 규칙은 유지한다.
week2의 동시성 제외와 활성 상품이 있는 브랜드의 삭제 거절은 week3에서 변경되는 부분이다.
week2의 기록을 소급하여 고치거나, 기존 Example 코드·무관한 구조를 함께 개편하지 않는다.

## 이번 작업의 실제 범위

2026-09-21에는 `volume-3/main`과 `volume-3/pr-01-plan` 생성 및 이 디렉터리의 문서 정리를 수행했다.
제품·테스트 코드와 기존 Docker·JPA 설정 변경은 이번 작업 대상이 아니다.
후속 요청에 따라 문서를 작업 브랜치에 커밋하고 두 브랜치를 원격에 푸시한다. 기준 브랜치는 출발 커밋을 유지한다.
테스트 실행과 PR 생성·병합은 포함하지 않는다. 이후 구현 상태는 [개발 계획의 진행 기록](development-plan.md)에 남긴다.
